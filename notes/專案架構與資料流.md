# 專案架構與資料流

> 探索日期：2026-10-13。內容依據 repo 現況（最後 commit 2023-06-21）與實際讀過的程式碼。

## 網站是什麼

「台南市議會觀測站」（https://tcco.tnsprout.org），台南新芽製作。提供四個功能，對應導覽列：

| 導覽列 | 路由 | 資料來源 |
|---|---|---|
| 看選區 | `/{屆}/district`、`/{屆}/district/{1st..13th}` | `district-map.json`、`meta-第N選區.md`、`sayit/stats.json` |
| 找議員 | `/{屆}/councilor`、`/{屆}/councilor/{議員id}` | `councilor-map.json`、`sayit/{id}.json`、`meta-第N選區.md` |
| 搜質詢 | `/{屆}/interpellation` | 預設清單來自 `sayit/*.json`，輸入關鍵字後改查 Algolia |
| 讀分析 | `/article`、`/article/{slug}`、`/article/category/{slug}` | `content/article/*.md`、`content/setting/*.json` |

「屆」在網址與資料夾中寫成 `3rd`、`4th`。

## 技術組成

- **Nuxt 4（Vue 3）靜態輸出**：`npm run generate` 從首頁、`/3rd`、`/4th`、`/about`、`/article` 開始沿著連結預先產生所有頁面，輸出到 `.output/public/`，部署到 GitHub Pages（`gh-pages` 分支，網域由 `static/CNAME` 指定）。2026-10 從 Nuxt 2 升上來。
- **資料讀取**：所有資料都放在 `tcw-ui/content/`。`server/utils/content.js` 讀 JSON，Markdown 用 `yaml` 解 frontmatter、`marked` 轉 HTML；`server/api/` 每個頁面一支，把原本 `asyncData` 的邏輯搬過去。頁面用 `useFetch` 取資料，generate 時資料寫進每頁的 `_payload.json`，正式站只有靜態檔。
- **模板與樣式**：Vue 檔用 Pug 模板 + SCSS（`lang="pug"`、`lang="scss"`），CSS 工具類用 tachyons，元件庫用 Buefy。`assets/variables.scss` 會自動注入所有 SCSS。
- **Decap CMS（後台，Netlify CMS 改名後的版本）**：`static/admin/`，`backend: github` 直接 commit 到 `main`。編輯者（主要是 littlesea922）透過 CMS 新增分析文章、修改選區說明與議員補充欄。git log 中「Create/Update 全站 | 分析文章 …」就是 CMS 產生的 commit。
- **Algolia**：搜質詢的全文搜尋。前端只用 search key，資料由 `tools/sync-search-index.js` 上傳。
- **PDF 原文檢視**：質詢卡片可以展開議事錄原文，用 pdf.js（CDN 載入）讀另一個 repo `tainansprout/tainan-council-data` 發布在 GitHub Pages 上的切片 PDF。詳見〈資料格式〉。
- **其他**：Sentry（`plugins/sentry.client.js`，有 `SENTRY_DSN` 才啟用，dev 不啟用）、Plausible（`@nuxtjs/plausible`）、`@nuxtjs/sitemap`（自動收 generate 出的頁面，輸出 `sitemap.xml`）、Jandi webhook（資料腳本出錯時通知）。

## 目錄（`tcw-ui/`）

```
pages/              路由。[[round]]/ 是首頁，[round]/ 底下是依屆次的頁面（[[x]] 是可省略的參數）
server/             讀 content/ 的 API（只在 dev、generate 時跑）
components/         共用元件（自動 import）
content/
  council/{屆}/     議員、選區、質詢資料（見〈資料格式〉）
  map/              台南鄉鎮區 topojson 與合併後的選區圖
  meta/             政黨、局處、同義詞、關於頁、雜項設定（CMS 可編）
  article/          分析文章（CMS 新增）
  setting/          文章分類（CMS 新增）
libs/               defs.js（預設屆次、選區對照）、utils.js、crawlerFriendly.js（SEO head）
tools/              資料腳本（Node，不會被打包進網站）
static/admin/       Decap CMS 設定
static/img/{屆}/    議員照片（由 get-councilors 下載壓縮）
static/content-img/ CMS 上傳的圖片
```

## 資料管線

四支腳本都在 `tcw-ui/` 底下執行，順序如下：

```
台南市議會官網 ──get-councilors.mjs──▶ content/council/{屆}/district-map.json
                                        content/council/{屆}/councilor-map.json
                                        static/img/{屆}/*.jpg
                                              │
content/map/town-2010.topo.json ─gen-district-map.js─▶ content/map/town-2010.topo-districts.json
                                              │
新芽人工編碼的 Google Sheet ─extract-interpellation.js─▶ content/council/{屆}/sayit/{議員id}.json
                                                        content/council/{屆}/sayit/stats.json
                                              │
                         sync-search-index.js ─▶ Algolia 索引
```

| 腳本 | 指令 | 輸入 | 輸出 |
|---|---|---|---|
| `get-councilors.mjs` | `node tools/get-councilors.mjs -r 4th` | 官網議員資訊網（`round-defs.js` 的 `councilorPageId`）、`content/meta/partyList.json`、`missing-councilor-list.json` | `district-map.json`、`councilor-map.json`、議員照片 |
| `gen-district-map.js` | `node tools/gen-district-map.js 4th [地圖檔名]` | `content/map/{地圖檔名}.json`（預設 `town-2010.topo`）、`district-map.json` 的 `townList` | `content/map/{地圖檔名}-districts.json` |
| `extract-interpellation.js` | `node tools/extract-interpellation.js -r 3rd` | `round-defs.js` 的 `sheetUri` + `sheetList`、`district-map.json`、`councilor-map.json`、`departmentBrief.json` | `sayit/{id}.json`、`sayit/stats.json` |
| `sync-search-index.js` | `node tools/sync-search-index.js 3rd [取樣%]` | `sayit/*.json`、`councilor-map.json`、`departmentBrief.json`、`synonym.json` | Algolia 索引（先寫 `{索引名}-new` 再 `moveIndex` 覆蓋） |

注意參數格式不一致：前兩支用 `-r`，後兩支用位置參數。

`gen-district-map.js` 只輸出一份選區圖，不分屆。台南第三、四屆的選區劃分相同，所以目前不用重跑。

## GitHub Actions

| Workflow | 觸發 | 做什麼 | Node |
|---|---|---|---|
| `ui-pull-request.yml` | PR 到 main | `npm ci` + `npm run lint` + `npm run generate` + `npm test` | 24 |
| `ui-deploy.yml` | push 到 main | `npm run generate:gh` → `npm test` → `sync-search-index.js`（預設 3rd）→ 部署 `gh-pages` | 24 |
| `daily-update.yml` | 每天 UTC 21:00 | `extract-interpellation.js`（沒帶 `-r`，見〈已知問題〉）→ `sync-search-index.js` → commit → generate → `npm test` → 部署 | 24 |

部署的是 `.output/public/`。`generate:gh` 會刪掉 `.output/public/admin`，所以正式站上沒有 CMS 後台；CMS 要從別的部署（或本機）進入。

## 已知問題

1. **每日更新實際上沒有更新質詢資料**：`daily-update.yml` 執行 `extract-interpellation.js` 時沒帶 `-r`。腳本 `main()` 在沒有 round 時 `return 1`，但沒有 `process.exit`，所以 exit code 為 0，CI 不會報錯，什麼都沒寫。自 2023-02-28「allow specify round info」那次 refactor 之後就是這樣。
2. **`getDistrictId()` 永遠回傳 undefined**：`extract-interpellation.js` 裡寫成 `districtName2Id[districtName]`，但 `districtName2Id` 是函式不是物件。結果是「先依選區找議員」這一步永遠失敗，全部落到「全市同名比對」。已檢查第三、四屆 `councilor-map.json` 都沒有同名議員，所以目前沒出錯。
3. **Algolia 只有一個索引、不分屆**：`sync-search-index.js` 每次用 `moveIndex` 覆蓋整個索引；前端搜尋也沒有依屆次過濾。也就是同時間只能搜一屆。另外上傳的欄位叫 `councilorRound`，`attributesForFaceting` 卻寫 `councilRound`，名稱不一致。
4. **前端只支援定期會原文**：`InterpellationCard.vue` 沒傳 `meeting-type` 給 `InterpellationSrcViewer`，永遠用 `regular`。如果之後要收臨時會的質詢，前端要補。
5. **預設屆次寫在兩個地方**：`libs/defs.js` 的 `DEFAULT_ROUND = '3rd'`，以及 `content/meta/misc.json` 的 `round-list[].isDefault`（頁尾的屆次切換）。
