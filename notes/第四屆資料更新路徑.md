# 把網站切換到第四屆資料：要做哪些事

> 探索日期：2026-10-13。只做探索與驗證，還沒動手改程式或資料。

## 現況：第四屆缺什麼

| 項目 | 第三屆 | 第四屆 |
|---|---|---|
| 議員與選區（`district-map.json`、`councilor-map.json`、照片） | 有 | 有，但停在 2023-02-28，之後的異動（例：張世賢身故）沒反映 |
| 選區說明、議員經歷（`meta-第N選區.md`） | 有 | 13 個檔案都是 0 bytes |
| 質詢資料（`sayit/*.json`） | 13,026 筆 | 只有一份全空的 `stats.json` |
| 議事錄 PDF 切片（`tainan-council-data`） | 第 1～6 次定期會 | 沒有 |
| 搜尋索引（Algolia） | 有 | 沒有 |
| 預設屆次 | `3rd` | — |

選區劃分兩屆相同（已比對 13 個選區的 `townList` 與名額），選區地圖不用重做。

**卡住的是質詢資料，不是程式碼。** 第三屆的質詢來自新芽人工編碼的 Google Sheet，`round-defs['4th']` 沒有 `sheetUri`／`sheetList`，所以 `extract-interpellation.js -r 4th` 只會產生空的 stats。

## 第四屆可用的原始資料

詳見〈台南市議會官網探索〉。重點：

- 第四屆共 8 次定期會：第 1～6 次有整本議事錄 PDF（已驗證第 6 次**有文字層**）；第 7 次（2026-06）議事錄尚未公布；第 8 次 2026-10 正在開。做完第 1～6 次後，第 7、8 次要等議會公布再補。
- 第 4～6 次另有 Word zip，`002市政總質詢/` 每天一個 docx、`003市政府業務報告及質詢/` 依部門分，發言人獨立成段（「林議員冠維：」「體育局陳局長良乾:」）。
- 已驗證可以自動找頁碼：docx 中林冠維質詢的句子「非洲豬瘟在22日爆發…」，去掉空白後在第 6 次定期會 PDF 全文比對，命中第 136 頁，該頁頁首也印「市政總質詢 136」。所以 `src` 欄位可以用「發言開頭兩句話在 PDF 哪一頁」自動回填。

## 步驟

### 1. 更新議員名單

```sh
cd tcw-ui
node tools/get-councilors.mjs -r 4th
git diff content/council/4th static/img/4th
```

- 檢查身故、辭職、遞補、補選的議員。官網已移除、但任期內有質詢的人，加到 `content/council/4th/missing-councilor-list.json`（格式參考第三屆的洪玉鳳）。
- 新增議員要在 `static/admin/config.yml` 的「第四屆 | 後設資料」對應選區加一行 `councilor-{id}`，CMS 才能編輯他的經歷。
- 政黨簡稱若不在 `partyList.json`，爬蟲會丟 `Undefined party`，要先在 CMS 補政黨。

### 2. 產生質詢資料（兩條路）

兩條路的終點都是**同一份 Google Sheet 格式**（欄位見〈資料格式〉），這樣 `extract-interpellation.js` 不用改，只要在 `round-defs['4th']` 填 `sheetUri` 與 `sheetList`。

**路線 A：照第三屆做法人工編碼**

開一份同欄位的 Sheet，由人逐條讀議事錄填寫。程式零改動，品質可控，但量大：第三屆 6 次定期會共 13,026 筆。

**路線 B：從議事錄自動抽取，人工校對**

1. **取得逐字稿：`../tncc-data` 已經做好了**（見〈tncc-data逐字稿清理資料〉）。第 1～6 次定期會的市政總質詢 140 份、業務報告及質詢 77 份，都已清成 `speaker,content` 的 CSV，發言人也正規化成「蔡育輝議員」「民政局姜淋煌局長」。直接從 `meeting-records/output/csv/` 讀，不用重新解析 Word／PDF。
2. **切出議員發言**：把同一位議員連續的發言（含官員回答）收成一段；日期取自檔名（29 份檔名沒有日期，要另外補）。發言人只接受能對上 `councilor-map.json` 的名字，對不上的（黏行殘留）回 tncc-data 修。
3. **用 LLM 把每段拆成質詢議題**：一位議員一天通常問好幾個議題，第三屆的 Sheet 是一個議題一列。LLM 產出「質詢內容」（摘要）與「質詢相關局處」（限定在 `departmentBrief.json` 的簡稱清單內）。回答官員的職稱（「體育局陳局長良乾」）可當局處的強訊號。
4. **「發言開頭2句話」直接從原文截取**，不交給 LLM 改寫，因為前端會拿它在 PDF 裡做高亮比對。
5. **回填頁碼**：把第 4 步的文字去空白後，在該次定期會 PDF 的逐頁文字裡比對，命中的頁序就是「議事錄頁碼開頭」。
6. 輸出成 CSV，匯入 Google Sheet 人工校對，再走路線 A 的後半段。

**路線 B 各步驟要不要用 AI（2026-10-13 評估）**

| 步驟 | 要不要 AI | 說明 |
|---|---|---|
| 發言人清理 | 不用 | 以「議員」結尾、但對不上名單的發言人列共 2,932 列，大多是寫法不同（黃肇輝／黄肇輝 1,299 列、施余興望全名 980 列、余祝青／余柷青 254 列…），用對照表就能處理。真正黏行的約 122 列，能用「名字結尾符合議員名單」切開；根本原因是 cleaner 把沒有標點的短回答（如「好」）接到下一行，可以改成「獨立成行的發言人標記一定斷開」 |
| 補日期 | 不用 | 從議事錄目錄或頁首抓 |
| 回填頁碼 | 不用 | 字串比對 PDF 全文。要先下載第 1～6 次定期會的 PDF（每本可達 300 MB） |
| 拆議題、寫摘要、標局處 | **要** | 市政總質詢加業務報告共 217 份、約 1,036 萬字。中文大約一字一 token，輸入約 1,000 萬 token 上下，輸出依議題數而定（第三屆 6 次定期會 13,026 題） |

路線 B 寫 LLM 批次標記腳本時，可以用 `llm-labeling` skill 的規範（可續傳、checkpoint、結構化輸出驗證）。

### 3. 製作議事錄 PDF 切片（在 `../tainan-council-data`）

```sh
# 每 10 頁切一份，三位數補零
cpdf 臺南市議會第4屆第1次定期會議事錄.pdf -split -chunk 10 -o 'interpellation/round/4th/regular/01/%%%.pdf'
# 壓縮
./tools/minify-pdf.sh <切好的資料夾> <輸出資料夾>
```

- 本機沒有 `cpdf`，可用 `brew install cpdf`，或改用 `qpdf --split-pages=10`、PyMuPDF（輸出檔名要改成 `001.pdf` 格式）。
- 份量：第四屆第 6 次定期會一本就 5,919 頁、296 MB；第三屆 6 次定期會壓縮後約 1.9 GB，repo 的 `.git` 已 1.4 GB。GitHub Pages 有站台容量上限，可以考慮只發布有被引用到的頁段（市政總質詢與業務報告），或改放其他靜態空間，再改 `InterpellationSrcViewer.vue` 的 `PDF_SRC_BASE`。

### 4. 產生 sayit 與搜尋索引

```sh
cd tcw-ui
node tools/extract-interpellation.js -r 4th
node tools/sync-search-index.js 4th
```

Algolia 目前只有一個索引，`sync-search-index.js` 會整個覆蓋。要決定：

- 只搜第四屆：直接跑上面指令，第三屆的搜尋就沒了。
- 兩屆都能搜：改成兩屆一起上傳（不要用 `moveIndex` 覆蓋單屆），前端搜尋加上 `councilorRound:{屆}` 的 facet filter，並修正 `attributesForFaceting` 裡拼錯的 `councilRound`。

### 5. 切換預設屆次

- `tcw-ui/libs/defs.js`：`DEFAULT_ROUND = '4th'`
- `tcw-ui/content/meta/misc.json`：`round-list` 的 `isDefault` 移到 `4th`
- `.github/workflows/daily-update.yml`：`extract-interpellation.js` 補上 `-r 4th`、`sync-search-index.js` 補上 `4th`（目前沒帶屆次，見〈專案架構與資料流〉的已知問題 1）
- `.github/workflows/ui-deploy.yml`：`sync-search-index.js` 補上屆次

### 6. 補 CMS 內容

在 CMS「第四屆 | 後設資料」填 13 個選區的選區情報、每位議員的公職經歷與任期狀態。這是編輯工作，不是程式工作。
